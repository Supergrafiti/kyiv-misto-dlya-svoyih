# Київ: місто для своїх
## Індивідуальне завдання № 1 — структура, дизайн і використання сайту

### 1. Проєкт

**Тема:** міський путівник Києвом.

**Мета:** познайомити відвідувачів з історичними й сучасними локаціями столиці та запропонувати два варіанти пішої прогулянки.

**Аудиторія:** мешканці й гості Києва, які хочуть відкрити цікаві місця, провести час із друзями та побачити місто по-новому.

**Назва:** «Київ: місто для своїх».

**Підзаголовок:** «Місця, атмосфера та маршрути, які допомагають побачити Київ по-новому».

### 2. Схема вебсайту

```text
РІВЕНЬ 1
Головна — index.html
│
├── РІВЕНЬ 2: Місця Києва — places/index.html
│   ├── РІВЕНЬ 3: Історичний Київ — places/historical.html
│   │   ├── Андріївський узвіз (блок на сторінці)
│   │   └── Софійська площа (блок на сторінці)
│   └── РІВЕНЬ 3: Сучасний Київ — places/modern.html
│       ├── ТРЦ Gulliver (блок на сторінці)
│       └── Оболонська набережна (блок на сторінці)
│
└── РІВЕНЬ 2: Київ для прогулянок — walks/index.html
    ├── РІВЕНЬ 3: Прогулянка з друзями — walks/friends.html
    │   └── Контрактова площа → Андріївський узвіз → Поштова площа
    └── РІВЕНЬ 3: Вечірній Київ — walks/evening.html
        └── Хрещатик → Володимирська гірка → Майдан Незалежності
```

**Разом: 7 окремих вебсторінок; 3 рівні — 1 + 2 + 4.**
Локації всередині сторінок третього рівня є змістовими блоками, а не додатковими рівнями вебсторінок.

### 3. Система навігації

- На кожній сторінці є логотип-посилання на головну й меню з трьома основними пунктами.
- Дві великі картки на головній ведуть до двох сторінок другого рівня.
- Кожна сторінка другого рівня має дві картки-посилання на свої сторінки третього рівня.
- Навігаційний ланцюжок показує місце відвідувача в структурі: наприклад, «Головна / Місця Києва / Історичний Київ».
- На внутрішніх сторінках є кнопка повернення до батьківського розділу.
- Меню повторюється у нижній частині сайту; на телефоні верхнє меню відкривається кнопкою «Меню».
- Усі основні переходи виконуються звичайними посиланнями й працюють без JavaScript. JavaScript керує лише мобільним меню.

### 4. Дизайн-концепція

**Ідея:** сучасний міський фотопутівник. Великі реальні фотографії передають атмосферу Києва, а короткі тексти й зрозумілі картки допомагають обрати місце або маршрут.

**Кольори:**

| Елемент | Колір |
|---|---|
| Синій акцент, посилання, логотип | `#294BA0` |
| Темно-синій фон нижньої частини | `#14294E` |
| Основний текст | `#152747` |
| Білий фон | `#FFFFFF` |
| Світлий фон інформаційних блоків | `#F2F4F8` |
| Жовтий акцент на головній і фото | `#FFE08A` |

**Шрифт:** Manrope з підтримкою української мови; файл шрифту збережений разом із сайтом.

**Композиція:** широкий фотобанер, виразний заголовок, вільні відступи, картки у дві колонки на комп’ютері та в одну на телефоні. Сторінки локацій поєднують фотографії й тексти; маршрути мають пронумеровані зупинки та підсумкові блоки.

**Доступність:** українська мова документа, один основний заголовок на сторінці, описи зображень, видимий фокус клавіатури, посилання для переходу до вмісту, підтримка зменшеної анімації.

### 5. Відкрити сайт на своєму комп’ютері

1. Розпакуй `kyiv-site.zip`.
2. Відкрий файл `index.html` у браузері.
3. Перевір переходи між розділами й сторінками. Інтернет для самого сайту не потрібний: фотографії, стилі та шрифт лежать в архіві.

Зберігай файли й папки разом. Для переходу до зовнішніх джерел фотографій потрібне підключення до інтернету.

### 6. Розмістити на платформі — Netlify

Найпростіший варіант для цього проєкту — завантаження готової папки через **Netlify Drop**. Це звичайний сайт на HTML, CSS і JavaScript; збирати його перед завантаженням не потрібно.

1. Розпакуй архів.
2. Відкрий [Netlify Drop](https://app.netlify.com/drop) і ввійди у свій обліковий запис.
3. Перетягни папку, **усередині якої одразу лежить `index.html`**, у зону завантаження.
4. Дочекайся публікації та відкрий адресу, яку надасть платформа.
5. Для оновлення зміни файли на комп’ютері й завантаж оновлену папку на сторінці розгортань того самого проєкту.

Тут переноситься готовий сайт на хостинг. Конструктори з візуальним редактором мають власні формати проєктів; архів призначений насамперед для платформ, які приймають HTML-файли.

Джерело: [офіційна інструкція Netlify щодо ручного завантаження](https://docs.netlify.com/deploy/create-deploys/).

### 7. Інший варіант — GitHub Pages

1. Створи репозиторій у своєму обліковому записі GitHub.
2. Завантаж вміст розпакованої папки: `index.html`, `places`, `walks`, `assets` та інші файли з архіву. Головний `index.html` має лежати у корені репозиторію.
3. Відкрий **Settings → Pages**.
4. Обери **Deploy from a branch**, гілку з файлами й папку **/(root)**; збережи налаштування.
5. Коли публікація завершиться, відкрий адресу зі сторінки Pages.

Джерело: [офіційна інструкція GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

### 8. Як редагувати самостійно

Відкрий розпаковану папку в текстовому редакторі, наприклад Visual Studio Code.

| Що змінити | Де шукати |
|---|---|
| Текст головної | `index.html` |
| Текст інших сторінок | Відповідний `.html` у `places` або `walks` |
| Кольори, шрифти, відступи | `assets/style.css`; основні кольори на початку у `:root` |
| Фотографії | `assets/images/` |
| Мобільне меню | `assets/main.js` |

**Приклад редагування:** знайди у потрібному HTML-файлі речення, зміни тільки текст між тегами та збережи файл. Онови сторінку у браузері.

**Заміна фото:** збережи нове фото у папці `assets/images`, зміни назву у `src` відповідного `<img>`, онови опис у `alt` і джерело зображення у нижній частині сторінки. Для заміни під тією самою назвою достатньо підмінити файл зображення.

Перед власними змінами зроби копію папки. В HTML немає прихованих сервісів, зовнішніх бібліотек чи обов’язкової прив’язки до платформи.

### 9. Що показати під час демонстрації

1. Головну сторінку, тему та підзаголовок проєкту.
2. Два розділи другого рівня.
3. По дві окремі сторінки третього рівня в кожному розділі.
4. Фотографії, тексти, два маршрути й кнопки повернення.
5. Роботу меню та зміну розташування блоків на вузькому екрані.
6. Схему структури, кольори та спосіб організації файлів.
